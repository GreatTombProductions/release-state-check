Method, limits and worked reads

Release State Check

What the page asks, what the answers mean, and the part you have to do yourself.

What the page reads

Your browser makes up to four requests, straight to the sources. Nothing passes through this site.

  1. Does the DOI resolve? doi.org/api/handles/… returns the address a DOI points at and when that address was last set. No record there means the DOI was never registered.
  2. Which agency holds it? doi.org/doiRA/… names the registration agency. The page reads two: DataCite, which holds most dataset DOIs, and Crossref, which holds most article DOIs. Any other agency is reported as not read.
  3. Is there a public record? DataCite’s public API (api.datacite.org/dois/…) or Crossref’s (api.crossref.org/works/…). A record gives the title, version field, dates, declared size, licence and links to other versions.
  4. If DataCite has no record, are there siblings? A count of public records under the same publisher prefix. This separates “this record is not public” from “this publisher lists nothing publicly”.

Why “resolves, no public record” means something

DataCite gives every DOI one of three states. A draft does not resolve. A findable DOI resolves and has public metadata. A registered DOI resolves, but its metadata is “not findable in DataCite Commons and … not retrievable via the Public API”. So a DataCite DOI that resolves and has no public record is in the registered state. DataCite’s documentation names two routes into it: a record that has not yet been made public, and a public record moved back because “a DOI is created by mistake or content is retracted”. The page reports the state. It cannot see which route was taken.

Rules it keeps

  • A source that fails to answer gives Unknown. An error is never shown as “no record”.
  • Sizes, formats and licences are printed as the publisher declared them. Nothing is measured.
  • “Names a newer record” comes only from the record’s own links (previous-version-of, obsoleted-by). A Crossref update notice (correction, addendum, retraction) is reported separately, as an update attached. The page does not guess from titles or dates.
  • When a record is one version under a parent, the page says so and links the parent. It does not work out which version is the latest.

The three delivery checks

A registry record is a declaration. Whether the files reach you is decided somewhere else. A browser page is not allowed to test another site’s downloads, so these are yours to run.

1. Read the download form, not the description

Open the download page and look at what the form lets you choose: the product list, the years, any version or variant control. That list is what is served. Compare it with the catalogue title. If the title promises day, night and average layers for 1975–2025 and the form offers one product and a year, you have learned something no description will tell you.

If you are comfortable with browser developer tools, open the Network tab and watch what the form sends. If the request carries no version field, you cannot choose a version, whatever the page text says.

2. If a file address refuses you, try a sibling on the same host

A 403 has two very different causes: the dataset is closed, or the host refuses your network. Ask the same host for a different dataset. If the sibling answers and yours does not, the refusal is about the dataset. Then the honest options are to wait, to ask the publisher, or to use a source the publisher’s partners offer. It is not a signal to look for a way around.

python3 check.py hosts "https://HOST/DATASET-A/file.tif" \
  --sibling "https://HOST/DATASET-B/" --sibling "https://HOST/DATASET-C/"

check.py needs Python 3 and nothing else. It makes one request per address, does not follow redirects (a redirect can be a login gate) and does not retry.

3. Before trusting a mirror, compare a window

A copy on someone else’s host may be the same data. Find out before you build on it. Ask the producer’s own map service for a small area at native resolution, read the same cells from the mirror, and compare cell by cell. A full match on a window lined up to the grid is good evidence the values are the producer’s. It is not proof that the files are identical, and it says nothing about areas you did not compare.

Also confirm who runs the mirror. A copy published by a named co-producer under a stated licence is a source. An anonymous re-upload is not.

Two worked reads, 11 November 2026

Both were read from public sources on that date. They show the method. They are not a standing report on either dataset: states change, and a read is only good for its date. Every address and status is in receipts/2026-11-11.json. Neither is a complaint about the publisher. Creating an identifier ahead of a release is ordinary practice.

What a reader can and cannot conclude. The form’s year range now matches the version 2.0 title and goes one year past the version 1.0 record. The registry record for version 2.0 is still not public, and the form names no version. So from public surfaces alone you cannot tell which version a given year’s file belongs to, or whether day and night layers come with it. Someone citing the version 2.0 DOI today is citing a record nobody outside the publisher can read. If the version matters to your work, look inside the first file you download and write down what you find, and ask the publisher which version the form serves.

What this is not

  • Not an availability service. Nothing runs after you close the page. It will not tell you when a record becomes public.
  • Not a verdict on a publisher. It reports states, not reasons.
  • Not a download check. The page never requests a data file.
  • Not complete. DOIs held by agencies other than DataCite and Crossref are reported as not read. Datasets with no DOI are out of scope for the page; the delivery checks still apply.
  • Not a way around a refusal. A 403 is recorded as a 403.

If the sources change their response formats, the page reports Unknown instead of guessing. The reading rules have a test file that runs through both the page’s code and check.py, so the two cannot quietly disagree.
