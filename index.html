Release State Check

A catalogue lists a new version. The paper cites a DOI. The download page offers something else, or nothing. Has the release actually been published, or only announced? Paste the DOI. This page asks the DOI system and the registry directly and tells you what each one says, with the time it asked.

No account. Nothing is stored. Your browser asks doi.org, DataCite and Crossref directly; this site never sees the DOI you check. How it reads, and what it cannot see

Try a record that resolves but is not public: 10.48690/he9y-d243. One with a public record: 10.5281/zenodo.20424537. These are live reads, so what you see is today’s state, not ours.

The middle row is the one catalogues hide. A DOI can resolve for months with no public record behind it, and a citation that carries it looks exactly like a citation to a released dataset.

The half this page cannot do

A registry record says what a publisher declared. It does not say what the download site hands out. Those disagree in both directions, and only the delivery side settles whether you can get the files. Three checks cover it, each a few minutes, none needing an account:

  1. Read the download form, not the description. The list of years or versions the form offers is what is served.
  2. If a file address refuses you, try a sibling. Another dataset on the same host tells “this dataset is closed” apart from “this host refuses me”.
  3. Before trusting a mirror, compare a window. A copy hosted by someone else is usable once a sample matches what the producer serves.
